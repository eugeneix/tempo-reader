# Темп: как запустить с аккаунтами на своём сайте

Приложение — одна HTML-страница. Сервер для неё писать не нужно: регистрацию, базу данных и хранение файлов берёт на себя **Supabase**. Это готовый бэкенд с бесплатным тарифом. Сама страница лежит на любом бесплатном хостинге статических файлов.

## Как это устроено

```
iPhone (Safari / иконка на экране «Домой»)
 └─ index.html  ← ваш хостинг: Netlify, GitHub Pages, Vercel, Cloudflare Pages
     ├─ IndexedDB на устройстве: книги и прогресс, работает без интернета
     └─ supabase-js ──► Supabase
                         ├─ Auth: регистрация по почте и паролю
                         ├─ таблица books: название, автор, место чтения, «прочитано»
                         └─ Storage, корзина books: тексты книг, папка у каждого пользователя своя
```

- **Сначала устройство, потом облако.** Книги открываются из памяти телефона, поэтому читать можно и без сети. Облако хранит копию и переносит её на другие устройства.
- **Синхронизация** запускается при входе, при возвращении в приложение и по кнопке «Синхронизировать сейчас». Место чтения уходит в облако через 1–2 секунды после паузы. Если одну книгу читали на двух устройствах, побеждает то, где читали позже.
- **В облако загружается уже извлечённый текст**, а не исходный файл. Поэтому EPUB весом 5 МБ превращается примерно в 1 МБ текста.
- **Безопасность.** Ключ `anon` в `config.js` публичный, его не нужно прятать. Чужие данные защищены правилами Row Level Security из `schema.sql`: каждый запрос видит только строки и файлы того пользователя, который вошёл.
- **Без настроенного облака** (пустой `config.js` или страница на claude.ai) приложение работает как раньше и хранит всё на устройстве.

## Файлы

| Файл | Что это |
|---|---|
| `tempo-reader.html` | Исходник приложения, его же видно на claude.ai |
| `build.js` | Собирает `web/index.html` для своего хостинга |
| `web/index.html` | Готовая страница. Её загружают на хостинг |
| `web/config.js` | Адрес и публичный ключ вашего Supabase |
| `supabase/schema.sql` | Таблица, корзина и правила доступа |

## Шаг 1. Создайте проект Supabase (5 минут)

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и нажмите **New project**. Придумайте пароль базы и выберите ближайший регион, например Frankfurt.
2. Откройте **SQL Editor → New query**, вставьте весь `supabase/schema.sql` и нажмите **Run**. Должно появиться «Success».
3. Сделайте регистрацию максимально простой: **Authentication → Sign In / Providers → Email** и выключите **Confirm email**. Тогда аккаунт создаётся сразу, без письма.
   Если подтверждение оставить включённым, приложение попросит пользователя подтвердить почту по ссылке из письма. Бесплатная почтовая рассылка Supabase отправляет всего несколько писем в час, поэтому для настоящего запуска подключите свой SMTP.
4. Откройте **Project Settings → API**, скопируйте **Project URL** и ключ **anon public** и вставьте их в `web/config.js`:

```js
window.TEMPO_CLOUD = {
  url: "https://abcdefgh.supabase.co",
  anonKey: "eyJhbGciOi..."
};
```

Ключ `service_role` в файл не вставляйте никогда: он открывает доступ ко всей базе.

## Шаг 2. Соберите страницу

После каждой правки `tempo-reader.html` пересоберите страницу (нужен Node.js):

```bash
node build.js
```

В папке `web/` окажутся `index.html` и `config.js`. Их и нужно загрузить на хостинг.

## Шаг 3. Опубликуйте в интернете

Самый простой способ — **Netlify Drop**:

1. Откройте [app.netlify.com/drop](https://app.netlify.com/drop) и войдите.
2. Перетащите папку `web` в окно браузера.
3. Через несколько секунд появится адрес вида `https://tempo-reader-123.netlify.app`. Его можно переименовать в настройках сайта.

Другие варианты:
- **GitHub Pages:** положите содержимое `web/` в репозиторий, затем Settings → Pages → Deploy from branch.
- **Vercel** или **Cloudflare Pages:** подключите репозиторий и укажите `web` как папку для публикации.

Хостинг обязательно должен работать по HTTPS. Все перечисленные дают HTTPS сами.

Затем в Supabase откройте **Authentication → URL Configuration**, впишите адрес сайта в **Site URL** и сохраните. Это нужно, чтобы ссылки из писем вели на ваш сайт.

## Шаг 4. Установите на iPhone

1. Откройте адрес сайта в **Safari**.
2. Нажмите «Поделиться» → **«На экран „Домой“»**.
3. Запустите «Темп» с иконки, нажмите на человечка в библиотеке и создайте аккаунт.

У приложения на экране «Домой» своя память, отдельная от Safari. Поэтому войдите в аккаунт именно там. Книги, загруженные до этого в Safari, подтянутся после входа, если в Safari вы тоже вошли.

## Как ведут себя данные

| Ситуация | Что происходит |
|---|---|
| Загрузили книгу, вы вошли в аккаунт | Книга сохраняется на устройстве и загружается в облако |
| Загрузили книгу без входа, потом вошли | При входе книга загружается в ваш аккаунт |
| Вошли на новом устройстве | В списке появляются книги с меткой «В облаке». Текст скачивается при первом открытии |
| Удалили книгу | Она удаляется на устройстве и в облаке, а при следующей синхронизации и на других устройствах |
| Вышли из аккаунта | Книги аккаунта удаляются с этого устройства, но остаются в облаке |

## Лимиты бесплатного тарифа Supabase

- 50 000 активных пользователей в месяц, база 500 МБ, хранилище 1 ГБ. Текстов этого хватит примерно на 1000–2000 книг.
- Один файл до 50 МБ. Это лимит в `schema.sql`.
- Если проектом не пользоваться неделю, бесплатный проект засыпает. Его можно разбудить в панели одной кнопкой.

## Что можно добавить потом

- **Вход по ссылке без пароля** (magic link): `signInWithOtp({ email })` вместо пароля. Для этого обязательно нужен свой SMTP.
- **Вход через Apple или Google:** включается в Authentication → Providers, в коде это `signInWithOAuth`.
- **Синхронизация настроек и статистики:** ещё одна таблица `profiles` с JSON-полем `settings`.
- **Сброс пароля:** `resetPasswordForEmail` и экран ввода нового пароля.
- **Офлайн-запуск без сети** через service worker: страница будет открываться даже в самолёте.
